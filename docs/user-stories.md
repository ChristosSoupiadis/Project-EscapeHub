# User Stories – EscapeHub

Το αρχείο περιέχει όλα τα user stories του project για τη διάρκεια των 8 εβδομάδων.
Για κάθε user story ορίζεται η εβδομάδα υλοποίησης και το μέλος που είναι υπεύθυνο.

Μέλη: **Α** Χρήστος Σουπιάδης · **Β** Αναστασία Τσιολπίδου · **Γ** Γεωργία-Κυριακή Δημητριάδου · **Δ** Γιώργος Βιτάσκος · **Ε** Γιώργος Μακρής

## Χρήστες και ομάδες

| ID | User story | Εβδομάδα | Μέλος |
|---|---|---|---|
| US-01 | Ο παίκτης πρέπει να μπορεί να κάνει εγγραφή με όνομα χρήστη και κωδικό. Δεν επιτρέπονται δύο ίδια ονόματα χρήστη και ο κωδικός αποθηκεύεται μόνο ως hash. | 1 | Β |
| US-02 | Ο παίκτης πρέπει να μπορεί να συνδέεται και να αποσυνδέεται. Σε λάθος στοιχεία εμφανίζεται μήνυμα. | 1 | Β |
| US-03 | Ο παίκτης πρέπει να μπορεί να δημιουργεί ομάδα με όνομα και να λαμβάνει κωδικό πρόσκλησης. | 3 | Β |
| US-04 | Ο παίκτης πρέπει να μπορεί να μπαίνει σε ομάδα με τον κωδικό πρόσκλησης. | 3 | Β |
| US-05 | Κάθε μέλος ομάδας πρέπει να βλέπει τα υπόλοιπα μέλη της ομάδας του. | 3 | Β |
| US-06 | Ο δημιουργός της ομάδας πρέπει να μπορεί να αφαιρεί μέλη από την ομάδα. | 5 | Β |

## Αποστολές

| ID | User story | Εβδομάδα | Μέλος |
|---|---|---|---|
| US-07 | Οι αποστολές πρέπει να διαβάζονται από αρχεία `.txt` στον φάκελο `missions/`. Μια νέα αποστολή προστίθεται με νέο αρχείο, χωρίς αλλαγή στον κώδικα. | 1 | Δ |
| US-08 | Ο παίκτης πρέπει να βλέπει τη λίστα των αποστολών με την περιγραφή και τις διαδρομές τους. | 1 | Δ |
| US-09 | Πρέπει να οριστούν το θέμα, η ιστορία και το περίγραμμα της πρώτης αποστολής. | 2 | Δ |
| US-10 | Όταν ένα αρχείο αποστολής έχει λάθος, το πρόγραμμα πρέπει να αναφέρει το αρχείο, τη γραμμή και το πρόβλημα. | 2 | Δ |
| US-11 | Πρέπει να υπάρχει MissionValidator που ελέγχει ότι η αποστολή είναι σωστή (π.χ. δεν απαιτεί γρίφο που δεν υπάρχει, έχει τελικό γρίφο). | 2 | Δ |
| US-12 | Το παιχνίδι πρέπει να περιέχει τουλάχιστον δύο ολοκληρωμένες αποστολές. | 6 | Δ |

## Γρίφοι

| ID | User story | Εβδομάδα | Μέλος |
|---|---|---|---|
| US-13 | Πρέπει να υπάρχουν γρίφοι με απάντηση κειμένου. Κεφαλαία, τόνοι και κενά δεν λαμβάνονται υπόψη και ένας γρίφος μπορεί να δέχεται περισσότερες από μία σωστές απαντήσεις. | 1 | Α |
| US-14 | Πρέπει να υπάρχουν γρίφοι που λύνονται με αναζήτηση στο Wikidata ή στο Open Library. | 1 | Α |
| US-15 | Πρέπει να υπάρχουν γρίφοι σειράς, όπου ο παίκτης δίνει βήματα με τη σωστή σειρά. | 2 | Α |
| US-16 | Πρέπει να υπάρχουν γρίφοι συνεργασίας, που λύνονται μόνο όταν κάθε μέλος δώσει το δικό του κομμάτι. | 2 | Α |
| US-17 | Κάθε γρίφος πρέπει να εμφανίζεται ως ανοιχτός, κλειδωμένος ή λυμένος. Ένας γρίφος ανοίγει όταν λυθούν οι γρίφοι που απαιτεί (RuleEngine). | 3 | Α |
| US-18 | Όταν λύνεται ένας γρίφος, η ομάδα πρέπει να κερδίζει το στοιχείο που δίνει ο γρίφος. | 3 | Α |
| US-19 | Ο παίκτης πρέπει να μπορεί να ζητήσει βοήθεια (hint), με ποινή χρόνου. | 6 | Α |

## Παιχνίδι και αποθήκευση

| ID | User story | Εβδομάδα | Μέλος |
|---|---|---|---|
| US-20 | Οι χρήστες, οι ομάδες και η πρόοδος πρέπει να αποθηκεύονται σε αρχείο, ώστε να μη χάνονται όταν κλείνει το πρόγραμμα. | 1 | Γ |
| US-21 | Κάθε ομάδα πρέπει να έχει μία κοινή συνεδρία ανά αποστολή, ώστε η πρόοδος ενός μέλους να φαίνεται σε όλα τα μέλη. | 1 | Γ |
| US-22 | Η ομάδα πρέπει να μπορεί να ξεκινά μια αποστολή και να τη συνεχίζει αργότερα από το σημείο που σταμάτησε. | 4 | Γ |
| US-23 | Πρέπει να υπάρχει κοινό ημερολόγιο στοιχείων της ομάδας, με το ποιος βρήκε κάθε στοιχείο και πότε. Πριν βρεθεί ένα στοιχείο φαίνεται μόνο ο τίτλος του. | 4 | Γ |
| US-24 | Πρέπει να καταγράφονται ο χρόνος και τα λάθη της ομάδας. Κάθε λάθος προσθέτει στον χρόνο την ποινή της αποστολής. | 4 | Γ |
| US-25 | Με τη λύση του τελικού γρίφου η αποστολή πρέπει να ολοκληρώνεται και να εμφανίζεται ο τελικός χρόνος της ομάδας. | 5 | Γ |
| US-26 | Πρέπει να υπάρχει κατάταξη των ομάδων που ολοκλήρωσαν κάθε αποστολή, ταξινομημένη με βάση τον χρόνο. | 6 | Γ |

## Εξωτερικά APIs και μενού

| ID | User story | Εβδομάδα | Μέλος |
|---|---|---|---|
| US-27 | Πρέπει να υπάρχει HttpHelper για κλήσεις HTTP με timeout 5 δευτ., το πολύ μία κλήση ανά δευτερόλεπτο και User-Agent με το email της ομάδας. | 1 | Ε |
| US-28 | Οι απαντήσεις των APIs (JSON) πρέπει να διαβάζονται χωρίς εξωτερική βιβλιοθήκη. | 1 | Ε |
| US-29 | Πρέπει να διερευνηθούν τα Wikidata και Open Library και να καταγραφούν τα endpoints που θα χρησιμοποιηθούν. | 2 | Ε |
| US-30 | Ο παίκτης πρέπει να μπορεί να κάνει αναζήτηση στο Wikidata ή στο Open Library μέσα από το παιχνίδι. | 4 | Ε |
| US-31 | Αν δεν υπάρχει internet ή το API δεν απαντά, πρέπει να εμφανίζεται κατανοητό μήνυμα χωρίς να κλείνει το πρόγραμμα. Οι γρίφοι αναζήτησης πρέπει να λύνονται και χωρίς internet. | 4 | Ε |
| US-32 | Πρέπει να υπάρχει μενού για όλες τις λειτουργίες: εγγραφή, ομάδες, αποστολές, παιχνίδι, κατάταξη. | 5 | Ε |

## Οργάνωση και ποιότητα

| ID | User story | Εβδομάδα | Μέλος |
|---|---|---|---|
| US-33 | Πρέπει να στηθεί το repo στο GitHub με τη δομή του project, README και κανόνες για branches και Pull Requests. | 1 | Α |

| US-35 | Πρέπει να καταγραφούν οι απαιτήσεις, η αρχιτεκτονική (διάγραμμα κλάσεων) και το backlog. | 2 | Όλοι |

| US-37 | Πρέπει να γίνει δοκιμή όλου του παιχνιδιού από την αρχή μέχρι το τέλος και να διορθωθούν τα λάθη που θα βρεθούν. | 7 | Όλοι |
| US-38 | Πρέπει να ετοιμαστούν το τελικό README με οδηγίες, η τελική αναφορά και η παρουσίαση. | 8 | Όλοι |
